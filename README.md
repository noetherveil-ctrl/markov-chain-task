# Генератор текста

Запуск:

```bash
python main.py austen.txt 100
python main.py austen.txt 100 --order 2
```

Проверка функций: `python -m doctest main.py`.

Без `--order` программа строит пары слов: по одному слову выбирает следующее.
С `--order 2` строит тройки: следующее слово зависит от двух предыдущих.
Повторяющиеся переходы остаются в списке, поэтому частые варианты выбираются чаще.

Взял два текста с Project Gutenberg:

- [Jane Austen, Pride and Prejudice](https://www.gutenberg.org/ebooks/1342) — 127360 слов.
- [Herman Melville, Moby Dick](https://www.gutenberg.org/ebooks/2701) — 212796 слов.

Перед запуском убрал служебный текст Gutenberg до и после книги.
Четыре результата по 100 слов находятся в `examples.txt`.

В тройках текст обычно связнее: модель учитывает два слова и чаще сохраняет
местные обороты исходника. В парах выбор свободнее, но фразы чаще теряют смысл.
Общего сюжета нет в обоих случаях, потому что модель помнит только ближайшие слова.

Если слово встретилось один раз и стоит в конце корпуса, продолжения для него
нет. Без проверки генератор остановится или получит ошибку при выборе следующего
слова. Здесь в таком случае выбирается новое начало с заглавной буквы, и генерация
продолжается до нужной длины.
